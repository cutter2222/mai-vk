# export

Слой экспорта: PDF через ONLYOFFICE, миниатюры через pypdfium2, автономный HTML из ComposedDeck, переиспользование превью, слоты рендера.

Вход: PPTX, ComposedDeck. Выход: PDF, PNG, HTML, манифест артефактов.

Есть с этапа 0A:

- `pdf.py` — `convert_to_pdf()`: ONLYOFFICE Conversion API, JWT, асинхронный опрос с общим тайм-аутом, ограниченный размер PDF, проверка PDFium и атомарная публикация. `office_source.py` — краткоживущая копия источника с подписанной ссылкой; очистка, изоляция от офисных ревизий и AI-исходников. Проверка рендерера при старте воркера (`pipeline/jobs.py: renderer_check`) использует этот же путь.
- `thumbnails.py` — `render_thumbnails()`: страницы PDF в PNG заданной ширины; все вызовы PDFium под одной блокировкой процесса, параллельность только процессами.

- `html.py` — `build_html()`: автономная страница колоды объектами слайда, а не его снимком (ТЗ п. 2.7: слайд-картинка не засчитывается). Всё берётся из ComposedDeck: рамка в долях холста → проценты, кегль в пунктах → `cqw` от ширины слайда, шрифт шаблона → `@font-face` с файлом того же резолвера, которым меряется вместимость слотов, картинки → `data:` из самого .pptx. Без обращений в сеть; текст выделяется и ищется.
- `deck.py` — `export_revision()`: экспорт ревизии варианта в staging: `deck.pdf` через ONLYOFFICE под слотом рендера, `thumbs/slide-NN.png` через PDFium (ширина `render.thumbnail_width_px`), `deck.html` через `html.build_html`. Если нативная разметка не построилась, HTML остаётся страницей из миниатюр с текстом под ними. В `RealLayers` недоступность конвертера — явная ошибка этапа; перехода на заглушку нет.

Осталось от этапа 9: кэш рендера и визуальное сравнение. Замеры и ограничения: `docs/pptx-capabilities.md`.

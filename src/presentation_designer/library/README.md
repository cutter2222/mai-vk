# library — собственные композиции

Слой отвечает на случай, ради которого он появился: пользователь загрузил не шаблон, а
прошлую презентацию, и её страниц не хватает под новый текст. Тогда колода либо складывается
из двух-трёх композиций подряд, либо теряет содержание. Библиотека даёт запас композиций,
которых в загруженном файле нет, и одевает их в его дизайн-систему.

**Порядок отбора не меняется: первыми идут паттерны загруженного файла.** Своя композиция
побеждает, только если заметно пригоднее лучшего паттерна шаблона (`BUILTIN_LEAD` в
`generation/matching.py`) — то есть когда шаблон не даёт нужной подачи или не вмещает
содержание. Сверх этого действуют два правила:

- **Служебные слайды** (титул, разделитель, оглавление, финал) берутся из шаблона всегда,
  когда такая роль в нём есть: это лицо колоды, и там почти всегда нарисован декор. Свои
  служебные композиции включаются, только если роли в шаблоне нет вовсе.
- **Медиа-композиции** (с картинкой или схемой) выбираются только под медиа-содержание. У
  образца шаблона картинка уже нарисована, и под текстовый тезис он выглядит цельно; у своей
  композиции на её месте было бы пустое место.

Замер 19.09.2026: на шаблоне VK Tech (53 паттерна) **13 из 13 слайдов собраны на паттернах
автора**; на фикстуре `mini_template` (4 паттерна, из них один содержательный) — 9 из 15 на
своих композициях.

## Состав

| Файл | Назначение |
| --- | --- |
| `spec.py` | Модель композиции: слоты, плашки, семейство с параметрами; загрузка состава |
| `geometry.py` | Раскладка семейств в долях холста и реестр `REGISTRY` |
| `tokens.py` | `DesignCode` — цвет, шрифт, кегль и пластика шаблона из `design_tokens` |
| `register.py` | Композиции → паттерны профиля с ёмкостью по метрикам шрифтов рендерера |
| `build.py` | Построение слайда на макете шаблона: плашки и текстовые рамки |
| `compositions/families.yaml` | Какие семейства включены и с какими параметрами |

## Универсальность

Композиция не знает ни одного шаблона. В `geometry.py` нет ни одного цвета и ни одного
кегля — только места под содержание в долях холста, поэтому одна раскладка работает и на
16:9, и на 4:3. Всё видимое названо ролью (`accent`, `muted`, `text`, `title`, `body`) и
берётся из `DesignCode` на сборке: палитра, шрифты, шкала кеглей, скругление плашек,
толщина обводки, наличие тени.

Количество набирается параметрами, а не числом файлов: `kpi_row` с `count: [2, 3, 4]` и
`card: [false, true]` — шесть композиций. **22 семейства текущего состава дают 52 раскладки**,
и это меняется правкой `compositions/families.yaml` без правки кода.

| Группа | Семейства | Что закрывает |
| --- | --- | --- |
| Текст и структура | `statement`, `bullets_pane`, `cards_grid`, `icon_cards`, `comparison`, `matrix`, `process`, `diagram_pane` | одна мысль, список, карточки с пиктограммами, две стороны, квадранты, шаги, схема из фигур |
| Числа и данные | `kpi_row`, `hero_number`, `chart_takeaway`, `chart_kpi`, `dashboard`, `table_sheet` | ряд показателей, главное число, диаграмма с выводом, диаграмма с показателями, несколько диаграмм, таблица |
| Изображения | `image_split`, `image_full`, `gallery`, `quote` | картинка и текст, кадр во всю ширину, галерея экранов, цитата с портретом |
| Служебные | `title_slide`, `agenda`, `section`, `closing` | титул, оглавление, разделитель, финал — на случай, когда их нет в загруженном файле |

Слоты таблиц, диаграмм, картинок, пиктограмм и схем создаются объектом-якорем: вёрстка
строит на его месте свой объект и якорь удаляет. Без якоря слот считался бы ненайденным, и
блок терялся бы (`build.ANCHOR_KINDS`).

## Как это попадает в конвейер

Анализ шаблона добавляет композиции в профиль обычными паттернами с
`source.kind = "builtin"` и `composition_id`. Дальше их видят все, кто читает профиль:
отбор кандидатов, короткий список для модели (`PatternInfo.summary`), лестница ёмкости,
вёрстка и интерфейс. Отдельной ветки «а если композиция наша» в планировщике нет.

Ёмкость слотов считается теми же метриками шрифтов рендерера, что и у паттернов шаблона, но
по кеглям дизайн-кода: в шаблоне с крупной типографикой та же композиция вмещает меньше, и
планировщик видит это до вёрстки.

Вёрстка (`layout/compose.py`) для `builtin` вместо клонирования образца строит слайд
**на макете шаблона** — фон, логотипы и колонтитулы приходят наследованием, а не копируются.
Дальше слоты заполняются общим путём по `element_ref`, и незаполненные карточки убираются
так же, как у образцов, через `removable_object_ids`.

## Границы

- Вид плашки задаётся только явными свойствами: ссылки фигуры на стиль темы обнуляются
  (`a:effectRef` и соседи), иначе одна композиция получает то тень, то чужую обводку.
- Композиция строится на самом пустом макете шаблона. Если у макета есть собственный
  сильный декор, он останется под композицией — это наследование, а не ошибка.
- Слоты таблиц и диаграмм композиция только размечает: объект создаёт вёрстка.
- Значки в собственных композициях — векторные из набора Lucide (`library/iconset`), подбор по
  смыслу текста по русскому словарю; фоновый мотив шаблона ставит `library/motif.py`.

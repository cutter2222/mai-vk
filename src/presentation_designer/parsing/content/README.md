# parsing.content

Импорт содержания: файлы проекта и бриф → ContentPackage (контракт 1.3).

- `parsers/` — парсеры по формату в общую модель блоков (`base.py`: заголовки, абзацы, списки, цитаты, код, таблицы, изображения с местом в источнике): `docx.py` (python-docx, стили заголовков и списков, подписи, картинки), `spreadsheet.py` (openpyxl и csv, форматы ячеек), `pdf.py` (pdfplumber для текста по кеглю и таблиц, pypdfium2 для картинок; скан помечается `no_text_layer`), `markdown.py` (markdown-it-py; txt по пустым строкам), `pptx.py` (python-pptx: текст, заметки, таблицы, данные диаграмм, картинки; файл не становится шаблоном), `image.py` (Pillow). `ParseCache` хранит разбор файла по sha256, формату, версии парсера и параметрам.
- `numbers.py` — числа, проценты, деньги, даты, диапазоны и кратности в русском и английском написании.
- `facts.py` — реестр фактов: контекст из предложения (показатель, период, субъект, сравнение), производные показатели («с 31 % до 44 %», первая и последняя строки набора данных), уточнение неоднозначных фактов моделью (скилл `content_importer`) с проверкой опоры подписи на фрагмент.
- `datasets.py` — наборы данных из таблиц: заголовки, типы колонок и единицы из форматов ячеек, заголовков и содержимого.
- `brief.py` — бриф из сообщения чата: скилл `brief_extractor` без рассуждения (`source: model`) и резервная эвристика (`source: heuristic`); поля без опоры в тексте отбрасываются.
- `importer.py` — сборка пакета: сквозные идентификаторы в порядке файлов, факты, недостающие данные по брифу, `import_meta` с версиями и ключом кэша; режим брифа без файлов не выдумывает показатели.

Слой не знает об HTTP, очереди и путях клиента: файлы приходят из хранилища загрузок (`pipeline/files.py`) по идентификаторам. Точки входа: `pipeline/real.py` (воркер), `cli/import_content.py`.

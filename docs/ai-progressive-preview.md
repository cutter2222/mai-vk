## Асинхронное отображение страниц

Реализован путь для **сохранённых офисных ревизий**, не потоковая генерация PPTX:

1. Один запрос конвертирует неизменяемый PPTX в PDF и растеризует первую страницу.
2. PDF, PNG первой страницы и manifest всех страниц публикуются атомарно.
3. Интерфейс запрашивает PNG независимо; внеэкранные миниатюры загружаются лениво.
4. Каждый недостающий PNG создаётся по запросу и атомарно публикуется. Повторные
   запросы одной страницы объединяются файловой блокировкой между процессами.
5. Номера страниц не зависят от порядка завершения запросов. Смена ревизии
   использует другой ключ. Ошибку страницы можно повторить, не открывая ONLYOFFICE.

PDFium остаётся под общей блокировкой процесса: параллельные HTTP-запросы
**не означают параллельных вызовов PDFium**. Параллельная растеризация отдельными
процессами не включена. Фоновая durable-очередь конвертации тоже не добавлялась.
Конвертация целого PPTX по-прежнему предшествует первому изображению.

Кеш `office-previews/v2-*` содержит PDF и PNG только запрошенных страниц.
Кеш v1 не перезаписывается. Автоматического GC этих каталогов пока нет.
Предварительно опубликованное превью библиотечного шаблона по-прежнему используется
для его нулевой рабочей ревизии. Серверные экспорт и аудит продолжают ждать полный
набор изображений: частичный preview не выдаётся за завершённый аудит.

### Как повторять

Seed запускается в окружении API с доступом к его OfficeStore. **Каждому запуску и
браузеру нужна новая копия**; retries отключить. Пример создания (каталог должен
отсутствовать):

```sh
docker exec -i presentation-designer-api-1 python - --out /app/runs/sdk-save-reopen-repeat \
  < ./scripts/seed_office_sdk.py
```

Из `./runs/sdk-save-reopen-repeat/seed.json` передать поля
`document_id` и `sha256` как `ONLYOFFICE_SDK_DOCUMENT_ID` и `ONLYOFFICE_SDK_SHA256`.
В окружении frontend с установленными Playwright/браузерами выполнить
`node ./frontend/node_modules/@playwright/test/cli.js test
./frontend/tests/onlyoffice-sdk.spec.ts --project=chromium
--workers=1 --retries=0` из `./frontend`, задав
`PLAYWRIGHT_BASE_URL` стенда. В контейнере использовать его абсолютные пути.
Браузеру должен быть доступен также адрес `onlyoffice.public_url` из конфигурации API;
`localhost` контейнера не является localhost машины.

В этой сессии использовались свежая отдельная production-сборка frontend и дополнительный
API-процесс на внутреннем порту 8001 с текущими исходниками, `reconcile=False` и
`lifespan="off"` (без фоновой сверки/GC и startup-очистки). Тестовый Caddy обслуживал
сборку и проксировал API/ONLYOFFICE; Playwright разделял его сетевой namespace, поэтому
`http://localhost:8080/onlyoffice` был доступен без правки основной конфигурации.
Подписанные source/callback/conversion обслуживались также основным API через общий
OfficeStore. Это не проверка новой версии callback в изолированном сервере.

Sandbox-документы намеренно остаются для диагностики: автоматического удаления
OfficeStore-копий не добавлено. Логи/артефакты не публиковать, особенно browser traces
с подписанными URL. После неуспешного теста проверить и закрыть именно его sandbox-сессию;
не сбрасывать чужие active_key. Тест не вызывает внутренние функции SDK, Plugin API или
Automation API. Добавление слайда здесь — действие пользователя на пустой синтетической
презентации, **не реализация AI-вставки с сохранением master/layout**.

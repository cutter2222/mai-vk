# Расширенная локальная приёмка ONLYOFFICE и OpenLux

Дата: 22 сентября 2026 по времени окружения. Стек: `http://localhost:8080`.
Артефакты: `./runs/acceptance-07/`.

## Итог

**Доставка ручных правок и ИИ-результата подтверждена. Полная сохранность оформления
после ручного редактирования в рабочем ONLYOFFICE не подтверждена: строгий аудит
выявил потерю точности вне выбранного объекта.** Пороги аудита не ослаблялись.

Рабочие контейнеры не пересоздавались, SDK и настройки провайдера не менялись.
Все операции выполнялись на семи новых sandbox-копиях VK Education (55 слайдов),
включая неуспешные попытки. Пользовательские ревизии не редактировались.
Исходный файл:
`./runs/save-reliability-04/sources/education.pptx`.

эквивалентность автоматически не доказана.

## Ручное редактирование брендового объекта

Уникальная замена на слайде 7:
«Пример оформления 4 текстовых блоков» → «Вариант оформления 4 текстовых блоков».

| Сценарий | UI-результат | Строгий аудит |
|---|---|---|
| Немедленно «Завершить и сохранить», без toolbar Save | passed, v0 → v1, same-page reopen | exit 1 |
| Toolbar Save, затем завершение и reopen | passed, toolbar v1, конечная v2 | exit 1 отдельно для v1 и v2 |

В успешных UI-прогонах no-op сохраняет исходный SHA-256; после ручной правки
сохранённый файл и файл после reopen совпадают. `active_key=null`, `error=null`.

У конечных ревизий обоих сценариев:
- 55 слайдов, намеренная текстовая замена сохранена;
- **63 изменения геометрии по −1 EMU**, включая макеты;
- неожиданные различия snapshot структуры на 25 слайдах;
- пиксельные различия на целевом слайде 7 и посторонних 18, 19, 33;
- максимальная доля изменённых пикселей вне цели около **0,1665%** (слайд 19).

Это сравнение одним конвертером ONLYOFFICE, а не доказательство точности PowerPoint.
Исходники и результаты аудита не переписывались и не «восстанавливались» из v0.
Аудиты: `manual-close-saved-audit/`, `manual-save-saved-audit/`,
`manual-save-toolbar-saved-audit/`; каждый имеет отдельные `.log` и `.exit`.

Рабочий образ: `presentation-designer/onlyoffice:latest`, image ID
`sha256:ada3baf45195c29b3a23e2c02f12c7dce9beddca1ae6287529a643a689f16cb1`.
Файловый SDK SHA-256:
`5ad873396344deedf33b03fb81a1b0421108ac4d7160dd58b6ca6d77c7ee90e7`.
Precision entrypoint отсутствует, `sdk-all.bin` присутствует. Это прежний SDK,
не ранее проверявшийся изолированный precision-кандидат. HTTP SDK hash в этих
UI-прогонах отдельно не фиксировался.

## Неуспешные попытки и изменения тестов

- `attempt-1/`: «Имя Фамилия» оказалось неуникальным — Replace All заменил девять
  объектов. Оба теста корректно отклонили результат. Изменились только sandbox-копии.
- `attempt-2/`: immediate close прошёл; explicit save остановлен SIGINT (exit 130)
  после ожидания неактивной кнопки Replace All. До toolbar Save он не дошёл.
  На скриншоте строка замены оказалась в поле поиска, поле замены пусто.
- Исправлена UI-последовательность: закрытие видимого уведомления What's New,
  явный Enter в поиске, ожидание enabled, проверка значений обоих полей,
  ограниченное ожидание нажатия. После этого **оба сценария прошли на новых копиях**.
- Параметризованы слайд/объект/инструкция ИИ-теста и текст ручной замены.
  Старые значения по умолчанию сохранены.

Изменены:
`./frontend/tests/office-ai-shortening-live.spec.ts` и
`./frontend/tests/onlyoffice-brand-live.spec.ts`.
Локальные runner/audit scripts находятся в каталоге артефактов; они рассчитаны
на установленный здесь Node и текущий локальный Docker-стек.

## Следующий технический барьер

Безопасная приёмка precision-кандидата на отдельном стенде с этим 55-слайдовым
документом, обоими режимами ручного сохранения и неизменённым строгим аудитом.
Перед переключением рабочего ONLYOFFICE необходимы согласованные browser/server
SDK, новый версионный URL для immutable browser cache, draining активных сессий
и проверяемый rollback. Эти условия описаны в
`./docs/office-save-fixes.md`.
Кандидат в этом этапе не выкладывался; удалённый сервер не обновлялся.

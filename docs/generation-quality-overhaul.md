# Качество генерации: разбор и доработка (24.09.2026)

Рабочий документ итерации. Изменения **не закоммичены**, коммит — только по просьбе пользователя.

## Как проверяли

Живые прогоны через API на четырёх шаблонах организаторов (скрипт `scripts/live_quality.py`,
материалы `examples/quality/*.md` и `examples/content`; старая копия — `runs/qa/harness.py`,
результаты итераций — `runs/qa/<итерация>-<сценарий>/`, контактные листы `*-contact.png`):

| сценарий | шаблон | вход |
| --- | --- | --- |
| ocean | VK Education | markdown, точно 8 слайдов |
| notify | VK Tech | examples/content (docx, xlsx, md, png), 10–12 |
| topic | VK WorkSpace | только тема (концепция), 8 |
| lct | ЛЦТ2026 | markdown с таблицей районов, 9–11 |

Итог (12 колод, 112 слайдов), ошибки аудита **без** `template.contrast`:
база — 74 (пустые слайды 12, переполнение 19, наложения 12, обрезка 6, сдвиг знаков 18);
финал `runs/qa/final-*` — 16 (переполнение 7, сдвиг знаков 8, наложение 1). `template.contrast`
(77) — в основном фирменные цвета шаблонов 3,4–4,1:1 (белый на синем VK), не дефект генерации.

## Что было не так и что сделано

1. **Модель возвращала пустые слайды**: в JSON-схемах ответа поля содержания были
   необязательны, декодирование по схеме их пропускало. Теперь обязательны
   (`STORY_MODEL_SCHEMA`: explanation, source_refs, fact_refs…; `PLAN_MODEL_SCHEMA`: text,
   items{sub,text,facts,icon}, facts).
2. **Планировщик не видел текста источника** — `packet_digest` передаёт текст блоков тезиса
   (`_thesis_sources`, подбор по словам, если нет source_refs).
3. Промпты: `story.outline` 0.3.1 (покрытие разделов, пояснения), `plan.slides` 0.5.1 (пункты
   из источника, заголовок ≤60 знаков, `icon`), `fill.slots` 0.2.0 (убран пример с выдуманными
   86 %), `import.fact_context` 0.2.0. Противоречие sub/text в политике концепции исправлено.
4. **Факты**: слабые подписи («дней», «м», «даёт») → неоднозначные, уточнение моделью для всех
   фактов из текста (пачки по 8, бюджет 60 с); `_fact_phrase` вместо «метрика: значение»;
   производные «изменения» только для временных рядов; русская запись чисел; факты тезиса не
   дописываются на каждый слайд — `_ensure_facts` по колоде; пустые картинки отсеиваются при
   импорте (`image_blank`, IMPORTER 0.3.2).
5. **Библиотека композиций**: цвет текста по реальному фону макета (`layout_background`,
   `legible`); кегли — медианы содержательных образцов с пределами читаемости.
6. **Анализатор** (0.4.3): ёмкость до соседа снизу (`clear_height`) и до препятствия в полосе
   (`clear_width`), плашка под заголовком растягивается (`backing`, `_fit_backing`).
7. **Подбор композиций** (`matching.py`): обложка — образец на титульном макете (`cover_like`),
   финал без образца — обложка; исключены: образцы без текстовых слотов, раздутые инфографики
   чисел, «неполные» карточки (`irregular_cards`), цитата не для цитат, образцы из одних подписей.
8. **Подгонка** (`fit_draft`): перебор с библиотечными композициями, пункты остаются пунктами,
   проверка сохранности содержания (`_keeps_content`, `_content_chars`), принудительная раскладка
   неразмещённого абзаца с переполнением (`force_text`), служебные слайды не меняют композицию.
9. **Колода**: дубли слайдов и заголовков, ослабленное слияние и `_fold_thinnest` вместо отказа
   `plan_slide_count`, пустые обязательные слоты прочерком «—».
10. **Вёрстка**: числа одной строкой (NBSP, уменьшение кегля), QR и аватары образца убираются,
    семантические иконки из каталога шаблона (`icon_for`, `_assign_icons`).
11. **Слой design**: поздняя замена композиций выключена (`design.feedback.pattern_swap: false`),
    обрубки слов и чужие факты/заголовки в дозаполнении отвергаются, идентификаторы `f11` → ссылки.
12. Аудит: «только заголовок» не ошибка на титуле/разделителе/финале.

## Что взято из PPTAgent (icip-cas/PPTAgent)

Разобраны три версии: v0.2.0 (статья EMNLP 2025: разбор образцов шаблона → схема элементов →
план → правка клона образца), v1.1.38 (DeepPresenter: свободная HTML-вёрстка и визуальная
проверка отрендеренного слайда моделью со зрением) и текущая main (навык для агентов, HTML →
PPTX). Наш конвейер по устройству ближе всего к v0.2.0 и большую часть её приёмов уже содержит:
функциональные слайды (титул, разделитель, финал) ставятся правилами, текст пишется в слоты
клона образца, длина текста ограничивается вместимостью слота, при переполнении текст сжимается.

13. **Разделы по частям рассказа** (приём `topic` из `pptagent/pptgen.py`,
    `_add_functional_layouts`): у тезиса обязательное плоское поле `part` — крупная часть
    рассказа. Если модель дала меньше двух разделов с содержанием (первый покрывает титул),
    `story._ensure_sections` строит разделы по смене `part`, а без него по заголовкам источника
    (`_heading_labels`: верхний уровень, встречающийся хотя бы дважды). Предупреждения
    `sections_from_parts` / `sections_from_headings`. `story.outline` 0.3.2, STORY 0.1.4.
    Ссылки заменённых разделов модели (модель ставит обязательные факты прямо на раздел)
    переходят к следующему тезису (`_hand_over_refs`), иначе план не проходит проверку связей.
    Раздел, названный целым выводом, получает короткое имя из `part`, вывод уходит в пояснение
    (`section_named_by_part`).
15. **Служебный текст разделов на слайдах**: модель пишет у раздела пояснение о самой
    презентации («Введение в раздел с планом действий», «Заключительный раздел. Резюме
    презентации»), а раздел без разделителя закрывается первым слайдом раздела — и слой design
    (`enrich`) брал это пояснение в основной текст. Пояснения разделов больше не материал
    (`design/fit._thesis_texts`, `variants._explanation`), подзаголовок разделителя не берёт
    пояснение о презентации (`_DECK_META`), промпт просит подводку для аудитории.
16. **Разделитель под длинное название**: заголовок разделителя рассчитан на пару крупных
    слов; раздел с названием длиннее 1,2 вместимости слота разделителя не получает
    (`_divider_fits`), место уходит содержанию (WorkSpace: «…требует пересмотра правил
    координации» гигантским кеглем вылезал за слайд).
17. **Диаграмма одной шкалы** (`_one_scale`): проценты и число пользователей на одной оси
    (VK Tech, метрики пилота) — проценты прижаты к нулю. Остаются ряды вида и единицы первого
    ряда с максимумами не дальше чем в 20 раз (`chart_series_dropped`).
18. **Базовый макет библиотечных композиций** (`library/register._base_layout`): у WorkSpace у
    всех макетов по одному плейсхолдеру, и все 52 композиции стояли на титульном макете с
    крупным декором — заголовок ложился на точки. Отсекаются макеты только служебных слайдов и
    с заголовком посередине высоты; у VK Tech, VK Education и ЛЦТ выбор не изменился.
    ANALYZER 0.4.4.
19. **Сбой рендера ONLYOFFICE**: после перезапуска API часть PDF вышла с перепутанными
    картинками макета (белый прямоугольник вместо «tech», фон кусками). Сам PPTX целый (связи
    и медиафайлы побайтно как в шаблоне), повторный экспорт того же файла чистый. Если листы
    выглядят так — повторить экспорт скачанного `deck.pptx` через
    `presentation_designer.export.office_download.export_revision` в контейнере API, прежде
    чем искать причину в коде.
20. **Подложка QR на финале VK Tech** (`pat_s5`): подпись «Вставить QR» шире белой плашки,
    и шаг 4 уборки (`_contains`: 80 % площади) плашку не находил. Теперь нужно, чтобы центр
    рамки лежал внутри плашки и перекрывалось не меньше 60 % площади. Белая карточка
    на `pat_s6` — часть фоновой картинки макета (самолётик из карточки), это замысел
    автора шаблона, не остаток образца.

Не взято и почему:
- выбор композиции моделью с обоснованием (`layout_selector`) — у нас детерминированный
  подбор по вместимости и виду подачи, он воспроизводим и не тратит вызов на слайд;
- «пишем текст под выбранный макет» (`editor` со `suggested_characters` и `default_quantity`)
  у нас частично: общие пределы в `plan.slides` и подсказка числа пунктов под композицию;
- визуальная проверка DeepPresenter (рендер слайда → модель со зрением → вердикт, проблемы
  с серьёзностью и `suggested_fix` → правка) — кандидат на следующий шаг: наш `auditor`
  нарочно не судит вёрстку, её считает код, а пустоты, перекос и «незаконченность» код не
  видит. Нужен замер, насколько `qwen3.8-27b` годится судьёй внешнего вида;
- PPTEval (оценки 1–5 по содержанию, дизайну, связности) — можно подключить к
  `scripts/live_quality.py` как метрику итераций, те же оговорки о модели-судье.

## Третий круг: незнакомые шаблоны (25.09.2026)

Проверка на 22 чужих шаблонах (`test_pptx/`: SlidesCarnival, шаблоны PPTAgent, пустой
python-pptx; в git не входит) показала: частные правки под четыре шаблона организаторов не
обобщаются. Переход к общим правилам:

1. **Пределы кегля по ширине слайда** (`capacity.min_pt_for`): Canva и Google Slides отдают
   холст 20 дюймов, там 12 pt — мелкий текст. Заголовок при переполнении уменьшается до
   предела роли, а не на половину кегля образца (образец «STEPS» в 62 pt).
2. **Разметка образцов**: служебные слайды сервисов шаблонов (Credits, How to use) не идут в
   подбор (`matching.vendor_meta`), колонтитулы-заготовки (`placeholder_markers`, адреса
   сервисов) убираются при вёрстке; шаблон из одних макетов собирается своими композициями.
3. **Проверка вёрстки по картинке** (скилл `visual_reviewer`, `audit/visual.py`,
   `pipeline/run._review_and_fix`): после экспорта каждый слайд смотрит модель со зрением
   (обрезка, наложение, мелкий текст, остатки образца, пустой слайд); композиции слайдов с
   дефектами запрещаются, план строится заново кодом, колода пересобирается; остаётся вариант
   с меньшим числом дефектов. На 16 размеченных слайдах модель верно отличила дефектный слайд
   от чистого в 15 случаях.
4. **Мерка**: `scripts/live_quality.py zoo` (все шаблоны папки на свои темы) и
   `scripts/vision_score.py <метка>` (доля слайдов с дефектом глазами модели).

Итоги на 8 худших шаблонах 16:9 (те же темы): слайдов с дефектом 51 % → 40 % (обрезка
13 → 4, пустые 14 → 11, мелкий текст 11 → 8); дефекты аудита 21 → 8. База на 22 шаблонах
(`runs/quality/base-1`): дефект на 42 % слайдов, больше всего — пустые слайды (31 из 185).

Время: одна презентация из трёх вариантов без проверки по картинке — 3,5 мин (OpenRouter,
рассуждение выключено); основной вариант собирается первым, два других — после него
параллельно (`jobs.ordered_variants`). Проверка добавляет 5–8 с на вариант, перестройка —
ещё 30–45 с там, где нашлись дефекты: замерить отдельно, цель — 5 минут на три варианта.

Дальше: пустые слайды (главный вид дефекта — композиция больше содержания), наложение
текста на фото в образцах, модель как судья для содержания (мусорные подписи карточек).

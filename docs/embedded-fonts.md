# Встроенные шрифты PPTX: извлечение в карантин

Реализация находится в
`/Users/nitemin/Desktop/mai-vk/src/presentation_designer/parsing/template/embedded_fonts.py`
и `/Users/nitemin/Desktop/mai-vk/src/presentation_designer/parsing/template/font_worker.py`.

## Что подключено

- Подготовка при загрузке PPTX, до публикации входа PDF-конвертера и до выдачи
  конфигурации просмотра/редактирования ONLYOFFICE, в том числе для старых загрузок.
- Разрешение `p:embeddedFontLst` → начертание → `r:id` → внутренняя связь типа `font`.
  Имена в теме, неиспользуемые content types и файлы без такой связи не извлекаются.
- Распознавание по байтам: самостоятельные TTF/OTF, EOT с MTX и/или XOR.
  XOR снимается до MTX. TTC/OTC, WOFF/WOFF2, неизвестные форматы не конвертируются.
  Для неизвестного содержимого с расширением ODTTF возвращается
  `odttf_unverified`: расширение не доказывает наличие Word-style обфускации.
- Проверка таблиц sfnt и разбор через fontTools: семейство, стиль, версия,
  права OS/2 и EOT, Unicode-покрытие, количество глифов, SHA-256.
  Restricted, bitmap-only и preview/print-only шрифты не сохраняются как кандидаты
  для редактирования. Это консервативная техническая политика, не юридическая экспертиза.
- Атомарный кэш по SHA-256 PPTX, версии обработчика и SHA-256 декодера.
  Исходный PPTX остаётся неизменным. Имена извлечённых файлов — только хэши.

Отчёт и кандидаты находятся под настроенным `data_dir/embedded-fonts`, например
`/Users/nitemin/Desktop/mai-vk/data/embedded-fonts/<pptx-sha>/v1-<decoder-sha>/report.json`.
Каталог не является системным каталогом шрифтов и не примонтирован в Document Server.
GET `/api/templates/{template_id}/fonts` возвращает отчёт, не сами файлы.
Ответы конфигураций ONLYOFFICE содержат дополнительное поле `font_report` вне JWT-конфига.

## Статусы и действия

| Статус начертания | Действие |
|---|---|
| `pending_review` | Проверить лицензию, полноту и конфликт с инвентарём целевого рендера. |
| `subset_quarantined` | Только документная изоляция; не глобальная замена семейства. |
| `identity_mismatch` | Сверить заявленные семейство/начертание с содержимым файла. |
| `conflict` | В пакете разные байты одного семейства/начертания; не выбирать автоматически. |
| `embedding_restricted` | Получить разрешённый полный шрифт; не обходить fsType. |
| `decoder_unavailable` | Установить закреплённый eot2ttf в образ или задать `PD_EOT2TTF`. |
| `unsupported_format`, `unsupported_eot` | Получить разрешённый самостоятельный TTF/OTF. |
| `invalid_relationship`, `external_relationship` | Исправить внутренние связи пакета. Внешние URL никогда не загружаются. |
| `invalid_font`, `invalid_eot`, `decode_failed` | Повторно экспортировать исходный файл/шрифт. |
| `size_limit`, `decode_timeout` | Проверить размер/сложность входа; лимиты автоматически не снимаются. |

`status=ok` на уровне отчёта означает завершённый обход, **не наличие всех шрифтов
в рендере**: отдельные начертания могут быть отклонены. `invalid_package` означает
ошибку пакета, `resource_limit` — неполный обход. `duplicate=true` означает одинаковые
байты внутри пакета, а не эквивалентность шрифту, установленному в ONLYOFFICE.
`coverage=unknown_fullness`: отсутствие subset-флага не доказывает полноту шрифта.

## Граница безопасности и незавершённая регистрация

**Автоматическая установка и обновление индекса ONLYOFFICE не реализованы.**
`registration=not_registered`, `renderer_availability=not_checked` не скрывают это.
Рендер продолжается с текущим набором шрифтов; извлечение само по себе не исправляет
подстановки. Инвентарь целевого Document Server ещё нужно сопоставить по
семейству/стилю/версии/хэшу/покрытию, а не по наличию имени в API-контейнере.

Native-декодер работает отдельным процессом: 8 с на начертание, общий бюджет 20 с,
CPU 6 с, файл до 16 МиБ, до 32 начертаний/64 МиБ входов, на Linux адресное
пространство до 512 МиБ, core dumps выключены. При тайм-ауте убивается группа процессов.
Переменные окружения приложения (включая секреты) не передаются.
**Это ресурсная изоляция, не полноценная sandbox:** процесс работает с UID приложения,
и нативная уязвимость потенциально даёт доступ к его файловой системе/сети.
Для недоверенного публичного сервиса перед включением native-декодирования требуется
отдельный непривилегированный сервис без сети/секретов и без общих writable-томов.
На macOS лимита address space нет. Дисковый кэш пока требует отдельной политики GC.

Безопасный следующий этап подключения — новый изолированный Document Server с
проверенным набором шрифтов и новым namespace кэша; существующие документы остаются
на старом сервере до закрытия. Нельзя автоматически регенерировать общий индекс,
перезапускать живой сервер или считать subset глобальным заменителем семейства.
Текущий код не меняет simplified editor и патч 40 → 16 мс.

## Декодер и лицензии

`/Users/nitemin/Desktop/mai-vk/docker/app.Dockerfile` собирает `umanwizard/libeot`
на commit `0407abddc581d32e9871ee41535183ee1d924d85` с `-DDECOMPRESS_ON`.
Исходный архив, MPL-2.0 LICENSE и PATENTS включены в образ под
`/usr/local/share/doc/libeot/`. PATENTS содержит оговорку о патентах Microsoft/Monotype:
это не юридическое подтверждение применимости патентных разрешений в вашей юрисдикции.
Перед распространением требуется правовая проверка. Сборка образа не означает
автоматическую выкладку и не перезапускает текущие контейнеры.

Локальные тесты (без установки шрифтов):

```sh
cd /Users/nitemin/Desktop/mai-vk
PD_EOT2TTF=/absolute/path/to/eot2ttf .venv/bin/pytest -q \
  /Users/nitemin/Desktop/mai-vk/tests/parsing/template/test_embedded_fonts.py
```

Без `eot2ttf` тесты реального декодера пропускаются; тесты ошибок и TTF/OTF остаются.
Проверка MTX использует закрытый VK Education из каталога организаторов; XOR-вариант
строится из тех же сжатых байтов. Несжатый EOT и TTF/OTF создаются тестами.

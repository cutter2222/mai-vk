## Выводы для промптов следующих этапов

Раздел написан по результатам прогонов 16.09.2026 (зонд перезаписывает таблицы выше; выводы при
следующем прогоне перепроверить).

- Endpoint — прокси LiteLLM над vLLM; в ошибках виден внутренний алиас модели `qwen3.8-27b-dflash2`
  (ревизия весов провайдером не раскрывается). `qwen3.8-27b` есть в `/models` и отвечает на обе роли.
- **Рассуждение включено по умолчанию.** `reasoning_effort` отклоняется (HTTP 400),
  `enable_thinking` в теле принимается, но не действует; работает только
  `chat_template_kwargs.enable_thinking` — стиль `vllm_chat_template` в `config/models.yaml`.
  Бюджет рассуждения не задаётся: рассуждение и ответ делят `max_completion_tokens`, поэтому при
  маленьком лимите ответ приходит пустым (`finish=length`, 20 токенов → `''`), а при среднем — JSON
  обрезается. Правило для скиллов: либо `reasoning: off`, либо лимит с запасом на рассуждение
  (в первом прогоне план из трёх разделов тратил ~250–420 токенов на рассуждение).
- `reasoning_tokens` в usage не приходит; текст рассуждения возвращается в `reasoning_content`,
  адаптер оценивает его в токенах и помечает `reasoning_estimated`.
- **У провайдера свой кэш по тексту запроса**: повтор того же сообщения возвращается за ~40 мс с
  прежним ответом, причём независимо от `chat_template_kwargs`. Для замеров свежей генерации
  (этап 11) входы должны отличаться; зонд добавляет уникальную метку в каждый запрос.
- Строгая `json_schema` работает и на тексте, и с изображениями; `json_object` тоже. Без рассуждения
  задача планирования (3 раздела) — 2,7–4,3 с, извлечение брифа — 0,5–0,7 с, чтение числа с
  картинки — 0,5–0,6 с, две картинки — 0,6 с; первый токен в потоке — 0,27 с.
- Одновременность: 4 параллельных запроса планирования завершились за 8,5 с без 429 (по одному —
  2,7 с): очередь на стороне провайдера растёт с уровнем, но отказов нет. Документированные квоты
  провайдером не сообщены — лимитер работает по умолчаниям `llm.concurrency=4`, `rpm=60`,
  `tpm=200000`; 8 не пробовался.

## Квоты

Документированные квоты провайдера (из настроек или аргументов зонда): одновременность —, RPM —, TPM —. Короткий зонд их не доказывает: наблюдаемая пропускная способность выше — это несколько запросов за секунды, а не минута под нагрузкой. В `config/models.yaml` записываются документированные значения, лимитер работает по ним.

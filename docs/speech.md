# Голосовой ввод в чате

Слева от «Отправить» в чате проекта — кнопка микрофона. Нажатие включает запись, повторное
(или Esc) выключает. Кольцо вокруг кнопки растёт с громкостью голоса — видно, что микрофон
слышит, ещё до первых слов. Пока человек говорит, текст идёт за речью: недоговорённая фраза
распознаётся черновиком примерно раз в секунду и сразу видна в поле, а когда фраза закончена
(пауза), черновик заменяет итог; пока фраза звучит или распознаётся, рядом мигает «…». Поле
с черновиком только для чтения — поправить текст можно, как только придёт итог. После
выключения текст остаётся в поле: его можно поправить и отправить обычной кнопкой — сообщение
уходит тем же путём, что и набранное. Enter отправляет то, что видно в поле (с черновиком), и
выключает запись.

Кнопки нет, если сервис распознавания не отвечает или у него нет весов
(`features.speech: false` в `GET /api/capabilities`), и если браузер не даёт микрофон
(`navigator.mediaDevices` есть только на HTTPS и localhost). Остальной чат работает как раньше.

## Модель

[GigaAM](https://github.com/salute-developers/GigaAM) (Сбер) — семейство Conformer-моделей для
русской речи, код и веса под MIT, 220 млн параметров. Берётся линия `v3_e2e_ctc`: только она
расставляет знаки препинания и нормализует текст (даты, числа), что для реплик в чат важнее
последних долей WER. Веса — чекпойнт `v3_e2e_ctc.ckpt` с CDN авторов (тот же, что
[`ai-sage/GigaAM-v3`, ревизия `e2e_ctc`](https://huggingface.co/ai-sage/GigaAM-v3/tree/e2e_ctc)),
словарь — sentencepiece.

Ограничения модели: только русский язык; запись до 25 с (длинные записи библиотека режет
pyannote с токеном Hugging Face — здесь это не нужно, см. ниже); распознавание офлайновое —
текст приходит фразой, а не по словам.

## Как устроено

```
браузер: микрофон → 16 кГц моно → детектор фраз → WAV
   → POST /api/speech/transcribe (API: проверка формата и длины, аудио на диск не пишет)
   → сервис asr: лог-мел на numpy → ONNX Runtime (GigaAM int8) → жадный CTC → текст
```

**Фразы режет браузер** (`frontend/lib/hooks/useDictation.ts`): `getUserMedia` с подавлением эха
и шума, `AudioContext` на 16 кГц (если браузер не соединяет микрофон с контекстом другой
частоты — Firefox, — контекст по умолчанию и пересэмплирование в коде), `AudioWorkletNode`
(запасной путь — `ScriptProcessorNode`). Детектор по энергии кадров 20 мс: порог — утроенный
уровень шума первых 300 мс, конец фразы — 700 мс тишины, фраза не длиннее 20 с, фрагменты
короче 300 мс речи не отправляются. Ответы дописываются в порядке фраз, даже если пришли не
по порядку.

**Черновики.** Модель офлайновая: слова по одному она не отдаёт, и без черновиков текст
появлялся бы только после паузы — при сплошной речи через много секунд. Поэтому, пока фраза
звучит, браузер отправляет её запись с начала с пометкой `?partial=1`: после 400 мс речи и
дальше раз в 700 мс новой записи, не больше одного запроса за раз, только пока фраза короче
12 с (дальше черновик дорог — ждём итога) и не в паузе: после 200 мс тишины фраза, скорее
всего, кончается, и черновик только задержал бы итог — сервис распознаёт запросы по одному. Черновик показывается после уже написанного текста
без последнего слова и конечной точки: запись обрывается посреди слова, и хвост черновика часто
недоговорён («укра», «деваст»). Итог фразы черновик заменяет; запоздавший черновик итог не
затирает. Для сервиса черновик — обычная фраза: распознавание фразы в 5 с — около 0,5 с одного
ядра.

**API** (`src/presentation_designer/api/routes/speech.py`): `POST /api/speech/transcribe`
(multipart, поле `audio`) проверяет WAV PCM16 моно 16 кГц, длину до `speech.max_seconds` (25 с)
и размер до `speech.max_bytes` (1 МБ) и пересылает байты в сервис через `httpx`. Ошибки:
`415 audio_format`, `413 audio_too_long`, `503 speech_unavailable` (сервис выключен, весов нет,
не отвечает). В журнал — только длительности, ни аудио, ни текст не сохраняются. В режиме
заглушек (`execution.mode: stub`) сервис не нужен: ответ — фиксированная фраза, чтобы
интерфейс и сквозные тесты работали без модели.

**Сервис `asr`** (`src/presentation_designer/speech/`, запуск
`python -m presentation_designer.cli.asr`): маленькое HTTP-приложение на стандартном
`http.server` — `POST /transcribe` и `GET /health`. Модель грузится при первой фразе и
выгружается после `speech.idle_unload_s` (10 минут) простоя; запросы идут по одному (одна
сессия ONNX Runtime на процесс, один поток CPU), после выгрузки процесс отдаёт память системе.
Отчёт `/health`: `loaded`, `unloaded` или `model_missing`.

**Признаки без torch.** `gigaam.onnx_utils` считает лог-мел через torchaudio, поэтому в образе
стека torch нет, а признаки считает свой код на numpy (`speech/features.py`): спектрограмма
мощности, мел-фильтры HTK, `log(clamp(x, 1e-9, 1e9))`; у v3 окно и БПФ по 320 отсчётов, шаг
160, без центрирования — параметры берутся из yaml экспорта. Окно и мел-фильтры — не
вычисленные заново, а буферы из весов (`preprocessor.npz`): в чекпойнте они округлены (до
0,002 от точных), и в тихих полосах признаки иначе расходились бы в лог-шкале на единицы.
С буферами из весов расхождение с torch — 0,00013 на записи-примере.

## Экспорт и веса

```bash
uv run scripts/export_gigaam_onnx.py --model v3_e2e_ctc --out models/gigaam/v3_e2e_ctc
make asr-model                       # веса на сервер: $SERVER_DIR/models, том сервиса asr
./deploy/deploy.sh --target server   # сервис asr в стеке
```

Скрипт экспорта запускается на машине разработчика, нужен интернет: зависимости (GigaAM с
torch, onnx, onnxruntime) он объявляет сам, `uv run` ставит их во временное окружение.
`gigaam.load_model("v3_e2e_ctc")` → `to_onnx` (fp32) → `onnxruntime.quantization.quantize_dynamic`
(int8, MatMul). В каталог модели ложатся оба графа, yaml экспорта, словарь, буферы признаков,
эталон признаков и `manifest.json`: версия GigaAM, ревизия весов (md5 и sha256 чекпойнта),
sha256 и размеры файлов, какой граф рабочий и контрольные распознавания torch, fp32 и int8 на
записи-примере и на пяти кусках по 14 с длинного примера из репозитория GigaAM. Если int8
ошибается по словам чаще fp32 больше чем на 2 %, рабочим остаётся fp32.

Каталог `models/` в `.gitignore`: веса не идут ни в Git, ни в образ. `make asr-model` переносит
на сервер только рабочий граф и мелкие файлы рядом.

**Замер экспорта 24.09.2026** (GigaAM 0.2.0, коммит 7447938d, torch 2.14, onnxruntime 1.23):
fp32 — 886 МБ, int8 — 320 МБ. На записи-примере и четырёх кусках из пяти int8 распознаёт
слово в слово как fp32; на одном куске одно слово из 150 отличается буквой — «возглащённые»
вместо «возглощённые», и оба — ошибка модели на «позлащённые» из текста Пушкина. WER int8
против fp32 — 0,7 %, рабочий граф — int8. ONNX fp32 совпадает с распознаванием самой
библиотеки на torch на всех кусках.

## Ресурсы

izbox.ru: 2 vCPU с AVX2, 3,9 ГБ памяти, ONLYOFFICE держит около 1 ГБ. fp32 в памяти — около
0,9 ГБ и туда не помещается; int8 — помещается: предел контейнера `asr` в
`docker/compose.prod.yaml` — 768 МБ и одно ядро.

**Замер на izbox.ru 24.09.2026** (int8, один поток):

| что | значение |
| --- | --- |
| контейнер `asr` без модели | 30–55 МБ |
| с загруженной моделью | 497 МБ из 768 МБ |
| загрузка модели по первой фразе | 2,5 с |
| запись-пример 11,3 с | распознавание 1,6 с, запрос из браузера 1,9 с |
| фраза 5 с | распознавание 0,51–0,57 с, запрос 0,68–0,71 с |
| выгрузка после простоя | через 600 с после последней фразы, память 497 → 55 МБ |

Чтобы загрузка модели не ложилась на первую фразу, интерфейс при включении микрофона
отправляет полсекунды тишины: модель грузится, пока человек начинает говорить. Сквозной
прогон с фальшивым микрофоном Chromium, который проигрывает запись речи
(`frontend/tests/chat-dictation-live.spec.ts`, модель в начале выгружена): три фразы появились в
поле через 1,7 / 0,9 / 1,1 с после конца каждой — с учётом 0,7 с тишины, по которым браузер
понимает, что фраза закончилась; повторный прогон с загруженной моделью — 1,5 / 0,9 / 1,0 с.
Живая диктовка человеком в чате на сервере этим прогоном не заменяется.

## Проверка

```bash
uv run pytest tests/speech tests/api/test_speech.py -q   # признаки, декодер, сервис, API
uv run pytest tests/speech -m model -q                    # с каталогом весов: запись-пример
make e2e                                                  # chat-dictation.spec.ts, Chromium
```

`tests/speech/test_features.py` сверяет лог-мел на numpy с эталоном torch (синтетический сигнал
— эталон лежит в тестах; запись-пример — эталон из экспорта), `test_decode.py` — жадный CTC и
словарь sentencepiece, `test_service.py` — ленивую загрузку, выгрузку по простою,
`model_missing`, одну очередь и HTTP-приложение, `test_transcribe_model.py` (метка `model`) —
распознавание записи-примера настоящей моделью. `frontend/tests/chat-dictation.spec.ts` —
фальшивый микрофон Chromium с синтетической записью из трёх фраз.

Запись-пример (`tests/fixtures/speech/example.wav`) скачивает скрипт экспорта из репозитория
GigaAM; в Git её нет.

## Этап: перенос рассчитанного текста в PPTX

- В сохранённом `rich/compact`, слайд 2, для `subtitle_1` план содержит
  `fit.lines=2`, `fit.max_lines=2`, `fit.size_pt=26`, но PPTX сохранил
  `a:bodyPr wrap="none"` из шаблона. Это объясняет горизонтальный выход текста
  при отсутствии расчётного overflow: измеритель переносит слова, а рендереру
  перенос запрещён.
- Композер теперь явно включает `wrap="square"` для текстовых блоков и списков
  с рассчитанным кеглем. Блоки без такого расчёта сохраняют поведение шаблона;
  прежнее исключение для однострочных чисел в крошечных слотах сохранено.
- Добавлены шесть регрессионных случаев: subtitle/body/bullets с `fit` и без него.
  Они проверяют записанный PPTX, полный текст, неизменную рамку и заданный кегль.
  До исправления три случая с `fit` падали на `word_wrap=False`; после — все шесть
  проходят. Ruff check/format, mypy двух backend-файлов и `git diff --check` прошли.
- Проверки после исправления: layout + generation — **238 passed**; полный
  `PD_TEST_LLM_MODE=replay .venv/bin/pytest -q` — **753 passed, 21 skipped**,
  4 deprecation warnings, exit 0. Лог полного запуска — локально
  `runs/layout-wrap/pytest.log`, код завершения — `runs/layout-wrap/pytest.exit`.
- Новый PDF/HTML-рендер и визуальная приёмка в этом этапе не выполнялись.
  Следующий этап — пересобрать и отрендерить `rich/compact`, проверить слайд 2
  и соседние подписи, затем продолжить разбор наложений и обрезания в mini/rich.
  Сохранность текста и корректный XML сами по себе не доказывают читаемость.

Последующая [узкая визуальная проверка](layout-wrap-visual-check.md) выполнена:

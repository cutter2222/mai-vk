## Предыдущая итерация: пустые разделители (27.09.2026)

Свежий просмотр шести replay-колод `mini/rich × compact/balanced/detailed` через
ONLYOFFICE показал конкретный дефект: в `balanced/detailed` появлялись отдельные
слайды только с названиями «Проблема», «Решение», «Результаты пилота», «План на
квартал», «Риски». Это не потеря текста и не проблема `DesignCode`, а лишние
разделители для секций, у которых был один содержательный тезис. Такой divider
раздувал колоду и выглядел как пустой слайд.

Исправлено в `src/presentation_designer/generation/variants.py`:

- divider теперь выбирается только для секции минимум с двумя содержательными
  тезисами;
- секция с одним тезисом использует заголовок своего content-слайда;
- секция без тезисов не получает отдельный слайд и покрывается обычной логикой
  покрытия обязательных тезисов;
- поздний добор divider больше не может вернуть секцию, исключённую из структуры.

Добавлены регрессии в `tests/generation/test_variants.py`:

- `test_single_thesis_sections_do_not_create_empty_dividers`;
- `test_multi_thesis_section_keeps_justified_divider`.

Результат после исправления:

- новые регрессии: **2 passed**;
- adaptive/content/process набор: **38 passed**;
- `test_compose.py`: **34 passed**;
- расширенный локальный набор без replay/cache-сценариев: **65 passed, 5 deselected**;
- Ruff и format для изменённых Python-файлов: passed;
- `git diff --check`: passed.

Старый сквозной replay после изменения закономерно дал **2 passed, 4 failed**:
изменение структуры `packet_digest` поменяло ключи запросов, а для четырёх новых
запросов нет LLM replay-записей. Это не замаскировано через `xfail`; нужны новые

## Цель

По входным материалам и теме генерировать три варианта презентации на основе
шаблона организатора так, чтобы одновременно сохранялись:

- фирменный дизайн шаблона и его `DesignCode`;
- исходные мастера, layouts, ресурсы и OOXML-связи;
- защищённые логотипы, фоновые и декоративные элементы;
- факты и текст входного материала без тихого удаления;
- адаптивная композиция для плотного и разреженного содержания;
- редактируемый PPTX, нативные таблицы/диаграммы и пригодный экспорт.

## Уже реализовано и подтверждено кодом

## Не считать завершённым

1. **Полная визуальная приёмка организаторских шаблонов.** Дизайн-слой сохранён
   архитектурно, но каждый свежий вариант ещё не просмотрен в полном размере.
2. **Adaptive layout после реального PPTX/PDF-рендера.** Известны случаи, когда
   расчётная capacity сообщает `0 overflow`, но LibreOffice/ONLYOFFICE показывает
   выход текста за край или наложение.
3. **Проверка плотных и разреженных входов.** Нужны dense/sparse сценарии для
   compact, balanced и detailed, включая длинные заголовки, карточки, числа и
   таблицы.
4. **Гарантия отсутствия тихого сокращения.** Текстовый слой PDF может содержать
   объект за границей страницы или под другим объектом; наличие текста в XML/PDF
   не доказывает видимость.
5. **Декоративные элементы при конфликте.** Нужно разделить намеренно снятую
   декорацию и ошибочно потерянный protected object в отчёте композиции.
6. **Replay fixtures и live inference.** После изменения структуры нужны новые
   записи ответов модели; затем необходимо выполнить свежие вызовы Qwen и полный
   runtime UI/API/RQ.
7. **Реальный полный runtime.** Не завершены в рамках этого статуса полный UI/API/RQ
   прогон и свежие вызовы Qwen; replay-тесты не являются live inference.
8. **Полный набор организаторских материалов.** Локальные targeted-тесты без
   `data/organizers/manifest.json` пропускают organizer-data тесты.

## Текущий рабочий приоритет

Порядок исправлений не менять без нового доказательства:

1. Повторить актуальный replay и настоящий экспорт шести базовых колод.
2. Проверить в полном размере: обрезку, наложение, мелкий текст, видимость
   protected objects, соответствие карточек и сохранность всех входных фактов.
3. Исправлять только воспроизводимый дефект: сначала добавить regression-тест,
   затем менять generator/layout.
4. Повторить тот же replay/PDF после исправления и сравнить отчёты до/после.
5. Расширить матрицу на четыре организаторских шаблона, три варианта и dense/sparse
   входы; затем выполнить live Qwen и runtime UI/API/RQ.

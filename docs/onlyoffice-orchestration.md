# ONLYOFFICE, AI и асинхронная генерация

Проверка локального стека 21.09.2026. Установлен Docs Community 9.3.1.

## Что исправлено

- Проект с выбранным шаблоном, но без generation job раньше показывал пустой
  собственный холст. Теперь открывается существующий TemplateSourceViewer в ONLYOFFICE.
  Это **просмотр исходника**, не редактирование библиотечного шаблона.
- После публикации первого PPTX вариант можно открыть, пока остальные варианты
  и аудит ещё выполняются. Привязка ProjectOffice к открытому артефакту сохраняется:
  фоновое обновление не уничтожает iframe и не подменяет пользовательский документ.
- Обычный вопрос больше не отправляется как ИИ-правка PPTX. Для правки текста
  открытого файла используется явная команда `/edit инструкция`; ограничения
  сохранения/закрытия сессии и проверки ревизии остаются в силе.
- POST /api/chat принимает project_id и event_id сохранённого сообщения. Контекст
  берётся с сервера: шаблон, материалы, бриф, настройки, generation status,
  число слайдов и состояние/число находок аудита выбранного варианта.
  Ответ сохраняется сервером. Подсказки-кнопки подставляют текст в поле ввода,
  **не выполняют действия автоматически**. Они пока не сохраняются при reload;
  сам ответ и история сохраняются. Повторный POST не дедуплицируется: автоматические
  повторы этого запроса не включены. Это следующий пункт усиления надёжности чата.
- Существующие анимация печати, reduced motion и временные отметки сохранены.
- Исправлен фильтр signed URL в access log: Uvicorn требует сохранить пять
  структурированных аргументов; секреты по-прежнему редактируются, но форматтер
  больше не падает на каждом запросе.

## Что поддерживает ONLYOFFICE

| Задача | Ответ |
| --- | --- |
| AI в редакторе презентаций | Да: официальный AI plugin объявляет EditorsSupport `slide`, minVersion 8.2.0. Это отдельный плагин, не наша серверная очередь. |
| Внешнее управление открытым документом через createConnector | Automation API относится к Docs Developer и оплачивается отдельно. Community-сборка проекта на него не опирается. |
| Создание/редактирование слайдов программно | Presentation API предоставляет объекты presentation, slide, master, layout, shapes, tables. Конкретный путь исполнения (плагин/Builder/Automation) и совместимость с 9.3.1 требуют отдельной проверки. |
| Асинхронные LLM-задачи без открытой вкладки | Выполняются нашим backend и worker queue. Наличие background-типа у AI-плагина не делает его серверным durable worker. |
| Постепенное появление слайдов прямо в живой сессии | В текущем проекте **не реализовано**. Публикация готового варианта — не потоковая вставка отдельных слайдов. |

В нашей конфигурации `customization.plugins: false`: встроенный AI-плагин не включён.
Его включение само по себе не подключит бриф, материалы, аудит, ретраи и очередь проекта.
В ходе этой задачи плагин, Automation API и новая лицензия не устанавливались.
Документация вендора уже описывает 9.4; её новые возможности нельзя автоматически
приписывать установленной 9.3.1.

## Рекомендуемая оркестрация

1. Backend — единственный владелец job, статусов и durable состояния. Модель предлагает
   структуру/контент; разрешённые действия исполняет сервер, не произвольный JS модели.
2. Зафиксировать story/order и стабильные slide_id. Независимые задачи слайдов могут
   завершаться в любом порядке. Публиковать результаты в исходном story order, с
   idempotency key, base_revision, ограничением concurrency, retry и cancellation.
3. Каждая публикуемая сборка — неизменяемый валидный PPTX + manifest + аудит.
   Не перезаписывать URL/байты, которые уже использует активный document.key.
4. В текущем Community-пути: показывать прогресс, открывать первый готовый вариант,
   остальные публиковать отдельно. Переход на другую версию — после сохранения и
   закрытия активной сессии, с явным подтверждением пользователя.
5. Для настоящей потоковой вставки: отдельный прототип собственного плагина-моста
   через поддерживаемый Plugin/Presentation API либо лицензированный Automation API.
   Сервер отдаёт проверенные декларативные команды. Мост применяет их последовательно
   и подтверждает operation_id; при reconnect не повторяет уже вставленные слайды.
6. При ручном редактировании генерационного слайда — блокировка этого слайда либо
   отдельная ветка/конфликт. Результат поздней LLM-задачи не может затереть ручную правку.
7. Приёмка моста: закрытая вкладка, reconnect, повтор события, отмена, out-of-order
   completion, два редактора, ручная правка во время генерации, сохранение и повторное
   открытие PPTX; проверка master/layout/theme и фактических шрифтов.

Пункты 2 и 5–7 — дальнейшая реализация/прототип, **не заявленные готовые функции**.
Встроенный AI может быть дополнительным пользовательским инструментом, но не заменой
template-adaptive анализа произвольных PPTX и серверной проверки качества.

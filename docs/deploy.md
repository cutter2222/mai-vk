# Развёртывание

Сервис работает на сервере Ubuntu в Docker Compose. Код живёт в репозитории, на сервере руками ничего не правится: любое изменение попадает туда через `deploy/deploy.sh`, который записывает commit и признак незакоммиченных изменений в `$SERVER_DIR/deploys.log`. Сервер заменяем: на нём только образы, собранные из репозитория, `.env` с настройками и данные в `$SERVER_DIR`. Сейчас стек состоит из входа Caddy и статического интерфейса в режиме заглушек; API, воркеры и Valkey добавляются на следующем этапе, резервные копии и прод-лимиты — после него.

## Требования к серверу

- Ubuntu 22.04 или 24.04 (подходит и Debian 12), архитектура x86_64 или arm64.
- SSH по ключу: root либо пользователь с `sudo` без пароля.
- Открытые порты 80 и 443. Внутренние порты сервисов наружу не публикуются.
- Адрес для HTTPS: свой домен с A-записью на сервер или имя вида `203-0-113-10.sslip.io` (точки IP заменены дефисами, домен не нужен). Сертификат Caddy получает и продлевает сам. Без HTTPS браузер не регистрирует service worker режима заглушек, а в рабочем режиме TLS нужен для загрузок и прямых ссылок.
- Для сборки интерфейса на сервере хватает 2 ГБ памяти. Если памяти меньше, образы собираются на машине разработчика (`--build-here`).

## Параметры сервера

Скопируйте `deploy/server.env.example` в `deploy/server.env` и заполните:

| Переменная | Значение |
| --- | --- |
| `SERVER_SSH` | `пользователь@хост` или алиас из `~/.ssh/config` |
| `SERVER_DIR` | корень сервиса, по умолчанию `/srv/presentation-designer` |
| `SERVER_URL` | объявленный адрес, только `https://…` |
| `SERVER_ALIAS_URLS` | необязательно: запасные адреса через запятую, которые Caddy обслуживает вместе с основным (например, `https://www.example.com,https://203-0-113-10.sslip.io`); имена с `www.` перенаправляются на `SERVER_URL` |

Файл в Git не попадает. Переезд на другой сервер — новый `deploy/server.env` и те же команды ниже.

## Установка

```bash
./deploy/install.sh --target server
```

Ставит Docker Engine и compose plugin из репозитория Docker, на машинах с памятью меньше 8 ГБ создаёт swap 2 ГБ, создаёт системного пользователя `presentation-designer`, каталоги `$SERVER_DIR/{repo,data,artifacts,runs,backups}` и файл `$SERVER_DIR/.env`. В конце печатает версии Docker, число ядер, память и свободное место. Повторный запуск безопасен. Обновление пакетов системы и отключение входа по паролю остаются за администратором сервера; `unattended-upgrades` в Ubuntu ставит обновления безопасности сам.

Секреты провайдера моделей (понадобятся со следующих этапов) вписываются в `$SERVER_DIR/.env` на сервере вручную, образец — `config/.env.example`. Строки `PD_PUBLIC_URL`, `PD_SITE_ADDRESS`, `PD_HTTP_PORT` и `PD_HTTPS_PORT` в этом файле переписывает `deploy.sh`, остальное сохраняется.

## Выкладка

```bash
./deploy/deploy.sh --target server    # или make deploy
```

1. Отправляет на сервер ровно те файлы, которые видит `git ls-files` с учётом `.gitignore`: без `.git`, локальных планов, материалов организаторов и `.env`. Дерево в `$SERVER_DIR/repo` заменяется целиком, устаревших файлов не остаётся.
2. Записывает адрес из `SERVER_URL` в `.env` сервера. Адрес не зашит в образы: интерфейс обращается к API того же origin, Caddy берёт имя сайта из переменной `PD_SITE_ADDRESS`.
3. Собирает образы на сервере (`docker compose build --pull`) и поднимает стек (`docker compose up -d --remove-orphans`).
4. Ждёт ответа `SERVER_URL` (первый сертификат занимает до минуты), проверяет, что отдаётся `mockServiceWorker.js`, и печатает адрес. Запросы готовности идут с самого сервера, чтобы не зависеть от VPN, прокси и DNS-кэша машины разработчика; внешнюю доступность подтверждает выданный сертификат. Если адрес не ответил, показывает хвост логов Caddy: чаще всего это DNS, который ещё не указывает на сервер, или закрытые порты 80/443. Если с машины разработчика адрес при этом не открывается, дело в её сети: VPN-клиенты нередко резолвят домен сами и держат старый адрес до истечения кэша.

`./deploy/deploy.sh --target server --build-here` собирает образы на машине разработчика под архитектуру сервера (`docker buildx`, эмуляция для x86_64 на Apple Silicon) и передаёт их через `docker save | docker load`; образ интерфейса весит около 25 МБ. Нужен серверам, которым не хватает памяти на сборку Next.js.

Повторная выкладка — та же команда: контейнеры пересоздаются только у сервисов, чьи образы или настройки изменились. `./deploy/deploy.sh --target server --down` останавливает стек, тома (сертификаты) и данные остаются.

## Проверка после выкладки

- `curl --fail "$SERVER_URL/"` отдаёт главную страницу; `curl -I "$SERVER_URL/mockServiceWorker.js"` — `text/javascript`.
- Сценарий в браузере по адресу сервера: главная → новый проект → шаблон и материалы в чат → бриф → генерация → варианты → аудит → скачивание. В шапке видны пометки «Режим заглушек» и «Сервис работает».
- Сквозные тесты против сервера: `PLAYWRIGHT_BASE_URL="$SERVER_URL" pnpm -C frontend test:e2e`.
- С этапа API: `curl --fail "$SERVER_URL/api/health"`. Сейчас `/api/*` отвечает 503 с JSON `api_unavailable`: в режиме заглушек запросы к API перехватывает service worker в браузере и до сервера не доходят.

## Логи и перезапуск

Команды на сервере из каталога репозитория (`$SERVER_DIR/repo`), с `.env` сервера:

```bash
cd /srv/presentation-designer/repo
docker compose -f docker/compose.yaml --env-file ../.env ps
docker compose -f docker/compose.yaml --env-file ../.env logs --tail=100 caddy
docker compose -f docker/compose.yaml --env-file ../.env logs -f frontend
docker compose -f docker/compose.yaml --env-file ../.env restart caddy
```

Журнал выкладок: `$SERVER_DIR/deploys.log` — время, commit, признак незакоммиченных изменений, ветка и адрес. Сертификаты Caddy лежат в томе `presentation-designer_caddy_data`; при `down` и повторном `up` они не запрашиваются заново.

## Откат

Образы собираются из состояния репозитория на машине разработчика, поэтому откат — выкладка нужного commit:

```bash
git stash            # если есть незакоммиченные изменения
git checkout <commit>
./deploy/deploy.sh --target server
git checkout main && git stash pop
```

Версии образов с тегами по commit и откат одной командой без пересборки появятся вместе с прод-конфигурацией.

## Локальный запуск того же стека

`make up` (то же, что `./deploy/deploy.sh --target local`) собирает и поднимает compose на этой машине по адресу `http://localhost:8080` с настройками из корневого `.env` (создаётся из `config/.env.example`). `localhost` для браузера считается защищённым контекстом, TLS не нужен. `make down` останавливает контейнеры. Локальный запуск служит отладке и серверную проверку этапа не заменяет.

# ИИ-правки PPTX: Unicode и сохранение смысла

## Изменения

- `text_context_json` показывает невидимые Unicode-разделители как JSON escapes,
  сохраняя читаемую кириллицу. Используется для deck/object/many и repair-подсказки.
  Ни исходник, ни `before` не нормализуются: посимвольное сравнение остаётся строгим.
- Подтверждена причина live-отказа: в новом диагностическом прогоне модель заменяла
  U+00A0 обычным пробелом в `before`; сохранены сырые ответы всех четырёх попыток.
  Это воспроизведение, а не восстановление сырых ответов предыдущего прогона.
- При сокращении проверяются лексические маркеры условий, отрицаний, исключений,
  модальности и заданного состояния; пустые и некоторые оборванные абзацы отклоняются.
  Проверка идёт после склейки runs и переносов, внутри существующего repair-loop.
- Числовая проверка теперь учитывает `±`, ранее потеря этого знака могла пройти.
- Инструкция модели требует законченных фраз, полноты перечислений, аудитории,
  характеристик и целей. Доля сокращения уступает сохранению фактов.

Защита выбранного объекта, точного `before`, геометрии, ревизии и атомарного
применения не ослаблена. Обычная замена текста без команды сокращения не ограничена
новыми смысловыми эвристиками. Существовавшие рабочие изменения сохранены.

## Регрессии

Новый `tests/generation/test_office_text_safety.py` проверяет реальные PPTX:

- потери «можно», «если возможно», «задан», исключений, отрицания и ±;
- законченные фразы из нескольких runs/переносов, слово на границе styled runs;
- Unicode в контексте и repair-подсказках без нормализации;
- повтор с исправлением и исчерпание повторов для deck/object/many;
- сохранность соседних объектов и остальных ZIP-частей.

Исходный набор: 15 failed / 2 passed до исправлений. После исправлений — все
121 office-тест прошли; полный backend — 790 passed / 21 skipped, exit 0.
Затем добавлены ещё 13 случаев: **134 office passed**, полный backend
**803 passed / 21 skipped**, 4 deprecation warnings, exit 0, 117,94 с.
Ruff check/format, mypy трёх production-модулей и git diff --check проверены.

## Живая проверка и ограничения

Локальные доказательства (не входят в Git):

- `runs/ai-object-live-02/`: диагностика before, сырые ответы, live-прогон,
  браузерный sandbox, Playwright-логи и скачанные PPTX;
- `runs/ai-object-live-03/`: повтор с уточнённым требованием полноты содержания,
  ответы, PPTX, 55-страничные рендеры и итоговый REVIEW.

Оба прямых live-прогона: три PPTX созданы, только целевой XML слайда изменён,
остальные 553 части сохранены; из 55 PNG изменился только целевой слайд.
Это техническая проверка, не автоматическое доказательство сохранения смысла.

Реальный Chrome/HTTP/OpenLux/ONLYOFFICE E2E для слайда 51 прошёл: выбор → ИИ-правка →
SDK no-op save → новая страница проекта → UI download. SHA-256 после правки,
сохранения, reopen и download совпадают; ревизия 0 неизменна. Структурный аудит
скачанного файла подтвердил сохранность вне выбранного объекта. В этом результате
сохранены и «вертикальной оси», и «можно», и «если возможно», и ±50% / 0%.
Это не проверка ручной правки в SDK и не браузерная проверка группового выбора.

Полная семантическая приёмка **не пройдена**: в прямом прогоне 03 текст `year`
потерял уточнения про молодёжь, ведущих экспертов и технологическую направленность;
в `percent` пропало «вертикальной». Лексические проверки не ловят все такие потери
и могут отвергать корректные синонимы. Они также не проверяют, что сохранённый
маркер относится к тому же утверждению. Нужна отдельная проверка покрытия фактов
или подтверждение пользователем до публикации, а не дальнейший список частных слов.

Usage отклонённых ответов всё ещё не полностью отражается в production-recorder;
в диагностических прогонах фактический usage каждой попытки сохранён отдельно.
API-маршрут выполняет правку напрямую, без RQ. Для E2E локальный API перезапущен
после проверки отсутствия активных редакторов/ИИ-блокировок и выполняемых заданий.
Создана только новая sandbox-копия, пользовательские документы не редактировались.

# Цифровой дизайнер презентаций

Сервис генерирует презентацию в стиле загруженного шаблона PPTX по контент-пакету или краткому брифу: разбирает дизайн-систему шаблона, планирует содержание, собирает слайды нативными объектами в трёх вариантах вёрстки, проверяет результат аудитом и экспортирует в PPTX, PDF и HTML.

Проект в разработке. Документация уточняется по этапам; текущее состояние описано ниже.

## Требования

- Python 3.12 и [uv](https://docs.astral.sh/uv/)
- Node.js 22 и [pnpm](https://pnpm.io/) 11
- Docker с compose plugin (для рендеринга и полного запуска)

## Подготовка

```bash
make setup          # uv sync + pnpm install
make gen-contracts  # Pydantic-модели и TypeScript-типы из contracts/schemas
make check          # контракты, ruff, mypy, pytest, eslint, tsc
```

Переменные окружения: скопируйте `config/.env.example` в `.env` в корне и заполните ключ провайдера моделей.

## Сервер и интерфейс

```bash
make api            # локальный API без Docker: задачи выполняются сразу, Valkey не нужен
make dev-real       # интерфейс на http://localhost:3000, /api проксируется на локальный API
make dev            # интерфейс в режиме заглушек: весь сценарий в браузере без backend
make e2e            # сквозные тесты в Chromium, Firefox и WebKit против статического экспорта
make build          # статический экспорт для сервера (рабочий режим, API того же origin)
```

Сервер — FastAPI (`src/presentation_designer/api`), состояние в SQLite, очередь RQ поверх Valkey: воркер анализа и исправлений и три воркера генерации. Слои конвейера пока заглушки с отметкой `execution_mode: stub` — они возвращают документы из примеров контрактов и настоящие открывающиеся файлы (PPTX, PDF, HTML, миниатюры), чтобы весь путь работал до подключения настоящих слоёв. Режим API интерфейса фиксируется при сборке переменной `NEXT_PUBLIC_API_MODE` (`real` по умолчанию, `mock` для заглушек в браузере): публичные переменные Next.js встраиваются в bundle. Экраны: `/` — сетка проектов (каждый проект — одна презентация с миниатюрой и состоянием); `/project?id=…` — редактор проекта: слева чат, в который пользователь бросает PPTX-шаблон и материалы и описывает задачу одной фразой (каждый шаг конвейера — карточка: шаблон, материалы, понятый бриф, ход задания, аудит), рядом вкладка «Файлы проекта»; справа предпросмотр (образцы шаблона до генерации, слайды вариантов с панелью аудита после); `/templates` — дизайн-системы шаблонов. Прежний адрес `/workspace?job=…` перенаправляет в проект. Проекты, файлы, бриф, настройки и лента чата хранятся на сервере: проект открывается по ссылке из любого браузера. Бриф из свободного текста извлекает `POST /api/brief`: пока детерминированная эвристика (`source: heuristic`), модель подключается на этапе импорта содержания.

## Развёртывание

```bash
make up             # весь стек в Docker Compose на этой машине: http://localhost:8080
make down           # остановить локальный стек
make test-server    # интеграционные тесты API и сквозные тесты интерфейса против сервера (или локального стека)
./deploy/install.sh --target server   # Docker и каталоги на сервере из deploy/server.env
./deploy/deploy.sh --target server    # выкладка: файлы по .gitignore, сборка образов, ожидание адреса
```

Сервер Ubuntu, Docker Compose: вход Caddy с автоматическим TLS, статический интерфейс, API, воркеры (образ с LibreOffice и шрифтами), Valkey. Адрес и SSH-доступ задаются в `deploy/server.env` по образцу `deploy/server.env.example` и в Git не попадают. Подробности: [docs/deploy.md](docs/deploy.md).

## Структура

| Каталог | Назначение |
| --- | --- |
| `contracts/` | JSON Schema документов между слоями, примеры, валидатор |
| `src/presentation_designer/` | ядро: parsing, generation, layout, export, audit, llm, pipeline, api, cli |
| `frontend/` | веб-интерфейс на Next.js и Mantine |
| `skills/` | версионируемые скиллы: манифесты и промпты |
| `config/` | настройки приложения и моделей |
| `docker/`, `deploy/` | образы, compose, Caddyfile, скрипты установки и выкладки |
| `tests/` | тесты по слоям и фикстуры |
| `docs/` | архитектурные решения, замеры, развёртывание |

## Ограничения

- Слои конвейера пока заглушки: результат помечен `execution_mode: stub` и не выдаётся за генерацию; настоящие парсинг, планирование, вёрстка, экспорт и аудит подключаются по этапам.
- Один арендатор без авторизации: все проекты видны каждому, кто открыл адрес сервиса.
- Извлечение брифа из фразы — эвристика без модели.

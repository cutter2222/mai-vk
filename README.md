# Цифровой дизайнер презентаций

Сервис собирает презентацию в стиле загруженного шаблона PPTX: разбирает дизайн-систему шаблона, планирует содержание по материалам или одной теме, верстает слайды нативными объектами в трёх вариантах, проверяет результат аудитом и отдаёт PPTX, PDF и HTML. Готовую колоду можно править в редакторе и из чата.

Решение команды «МАИ» для задачи 4 от VK Tech: сервис «Цифровой дизайнер презентаций», который помогает создать качественную презентацию в заданном шаблоне на основе текстового описания. Состояние на 29 сентября 2026.

## Что умеет

- **Любой шаблон PPTX.** Палитра, шрифты, макеты, композиции слайдов, значки и фоновый декор берутся из файла, а не задаются руками. Проверено на 4 шаблонах организаторов и 23 чужих.
- **Три варианта вёрстки** одной презентации: компактный, сбалансированный, подробный. Переключаются в шапке проекта; недостающий собирается оттуда же.
- **Материалы любого вида:** docx, xlsx, csv, pdf, markdown, txt, pptx, картинки — или одна тема без файлов (данные ищутся в интернете и ставятся с источником).
- **Нативные объекты:** текст, таблицы, диаграммы, схемы и значки редактируются в PowerPoint, а не лежат картинками.
- **Факты без искажений:** числа из материалов подставляет код по ссылке на источник, модель их не переписывает.
- **Аудит каждой колоды:** проверки по файлу и по отрендеренной странице (переполнение, наложения, контраст, шрифты, постоянные элементы) плюс проверка вёрстки глазами модели с перестройкой дефектных слайдов.
- **Редактор в браузере** на ONLYOFFICE: слайды выглядят как в PowerPoint, правки руками сохраняются сами.
- **Правки из чата и голосом:** выберите слайд или объект и напишите или надиктуйте, что изменить — меняется только он.

## Как это работает

```
шаблон PPTX ─▶ разбор шаблона ─▶ профиль ─┐
                                          ├─▶ смысловой план ─▶ три плана слайдов
материалы ───▶ импорт ─────────▶ пакет ───┘                          │
                                                                     ▼
                     аудит ◀── PDF, HTML, миниатюры ◀── вёрстка PPTX
```

1. **Разбор шаблона** — макеты, композиции со слотами и их вместимостью, дизайн-токены, значки, декор.
2. **Импорт материалов** — блоки текста, реестр фактов со ссылкой на фрагмент источника, наборы данных.
3. **Смысловой план** — один на содержание: тезисы, разделы, покрытие обязательных фактов.
4. **Планы трёх вариантов** — подбор композиции под каждый тезис и подгонка текста под вместимость.
5. **Вёрстка** — клон образца шаблона или собственная композиция в его дизайн-коде, затем отделка.
6. **Экспорт и аудит** — PDF и миниатюры через ONLYOFFICE, автономный HTML из объектов, отчёт проверок.

Слои обмениваются JSON-документами по схемам из `contracts/`, поэтому каждый запускается отдельно и подменяется заглушкой. Подробнее — [ARCHITECTURE.md](ARCHITECTURE.md).

## Быстрый старт

Нужен Docker с compose.

```bash
cp config/.env.example .env    # впишите ключ провайдера моделей
make up                        # весь стек: http://localhost:8080
make down                      # остановить
```

Дальше в браузере:

1. Создайте проект, выберите шаблон из библиотеки или бросьте свой PPTX в чат.
2. Опишите задачу и добавьте материалы.
3. Запустите генерацию: первый вариант открывается сразу, остальные дособираются в фоне.
4. Правьте в редакторе или из чата; выбранный слайд или объект показан плашкой над полем ввода.
5. Скачайте PPTX, PDF или HTML кнопкой «Скачать».

Готовую презентацию тоже можно открыть: бросьте PPTX в чат и выберите «Открыть как презентацию».

## Сдача: девять колод

Один контент-пакет (`examples/content`: docx, xlsx, заметки, картинка графика, бриф) на три шаблона организаторов в трёх вариантах, каждая колода в PPTX, PDF и HTML.

| Шаблон | compact | balanced | detailed | Время задания |
| --- | --- | --- | --- | --- |
| VK Education | 10 слайдов | 12 | 12 | 15 мин 31 с |
| VK WorkSpace | 11 | 12 | 12 | 12 мин 18 с |
| VK Tech | 11 | 12 | 12 | 12 мин 17 с |

- **Файлы:** `runs/quality/submission-final-decor/submit-{edu,workspace,tech}/{compact,balanced,detailed}.{pptx,pdf,html}`. Каталог `runs/` в Git не входит.
- **Собрать заново:** `uv run python scripts/live_quality.py submission --label <метка> --parallel 3`.
- **Проверка:** 104 слайда, все девять вариантов собраны; дефектов вёрстки по аудиту 6; заглушек, сырых маркеров фактов и пустых слайдов нет.
- **Модель этой сборки.** Модель решения — открытая Qwen 3.8 27B (Apache-2.0). Квоты на неё у команды на момент сборки не было, поэтому колоды собраны через мост разработки к закрытой модели, который в решение не входит; в метаданных каждого плана это отмечено (`license: proprietary`). Роли моделей переключаются строками в `.env`, код от модели не зависит ([MODELS.md](MODELS.md)).
- **Время.** На мосту 12–15 минут на три варианта: он отвечает по одному запросу. На Qwen с параллельными запросами — 2–4 минуты (замер 25.09, [docs/evaluation.md](docs/evaluation.md)).

## Разработка

Нужны Python 3.12 с [uv](https://docs.astral.sh/uv/), Node.js 22 с [pnpm](https://pnpm.io/) 11 и Docker.

| Команда | Что делает |
| --- | --- |
| `make setup` | зависимости backend и интерфейса |
| `make check` | контракты, ruff, mypy, pytest, eslint, tsc |
| `make api` | локальный API без Docker и очереди |
| `make dev-real` | интерфейс на `localhost:3000` с локальным API |
| `make dev` | интерфейс на заглушках, без backend |
| `make e2e` | сквозные тесты интерфейса |
| `make gen-contracts` | модели Pydantic и типы TypeScript из схем |
| `make organizer-data` | шаблоны организаторов в `data/organizers/` для тестов |

```bash
uv run pytest -q -m "not organizer_data"    # основной набор, около 3 минут
uv run pytest -q -m organizer_data          # шаблоны организаторов
```

Каждый слой запускается отдельно:

```bash
uv run -m presentation_designer.cli analyze шаблон.pptx --out runs/analyze
uv run -m presentation_designer.cli import examples/content/ --out runs/import
uv run -m presentation_designer.cli story runs/import/package.json --out runs/import/story.json
uv run -m presentation_designer.cli plan runs/import/story.json runs/analyze/profile.json \
    --content runs/import/package.json --out runs/plan
uv run -m presentation_designer.cli compose runs/plan/balanced.json \
    --profile runs/analyze/profile.json --template шаблон.pptx \
    --content runs/import/package.json --out runs/compose
```

Флаги, правила слоёв и отладка заданий — [docs/pipeline.md](docs/pipeline.md).

## Ограничения

- Слайды появляются вариантом целиком, а не по одному в открытом редакторе.
- Правки руками живут в офисной копии и в другой вариант не переносятся.
- Команда `/edit` правит текст открытого PPTX; слайды добавляются и удаляются в редакторе.
- Генерация изображений моделью не подключена: значки — из набора Lucide, фото — из CC0-фотобанков.
- Схемы строятся из фигур и соединителей, а не как SmartArt.
- Проприетарные шрифты без лицензии (VK Sans, Segoe UI) при рендере заменяются с предупреждением; в PPTX остаётся исходное имя.
- PDF без текстового слоя не распознаётся.
- Один арендатор без авторизации: проекты видны каждому, кто открыл адрес.
